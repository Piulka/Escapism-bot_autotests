# Escapism — автотесты

Pet-проект автоматизированного тестирования web-игры Escapism, запускаемой как
VK Mini App. Тесты воспроизводят пользовательские действия через UI, а API
используется для подготовки данных и проверки итогового бизнес-состояния.

Автотесты написаны на Python с использованием pytest и Playwright.

## Технологии

- Python 3.14
- pytest 9
- Playwright
- pytest-playwright
- python-dotenv

## Покрытие тестами

Текущее smoke-покрытие:

### Инвентарь

- Экипировка предмета
- Снятие экипированного предмета

### Навыки

- Прокачка навыка до первого уровня
- Списание очков обучения (LP)

Новые сценарии будут добавляться по мере развития функциональности приложения.

## Установка

### 1. Создать виртуальное окружение

```powershell
python -m venv .venv
```

Активировать:

```powershell
.venv\Scripts\Activate.ps1
```

### 2. Установить зависимости

```powershell
pip install -r requirements.txt
```

Установить Chromium для Playwright:

```powershell
playwright install chromium
```

### 3. Настроить переменные окружения

Создать файл `.env` на основе `.env.example`:

```env
BASE_URL=https://example.com/
API_URL=https://api.scripthub.ru/api/
VK_LAUNCH_PARAMS_USER_1=?vk_user_id=...
VK_LAUNCH_PARAMS_USER_2=?vk_user_id=...
```

`API_URL` должен заканчиваться символом `/`, потому что API-клиент использует
относительные пути эндпоинтов. VK launch params передаются полной query-строкой,
включая ведущий `?`.

Файл `.env` содержит данные авторизации тестовых пользователей и не должен попадать в Git.

## Запуск тестов

Запустить все тесты:

```powershell
pytest
```

Запустить только smoke-тесты:

```powershell
pytest -m smoke
```

Запустить тесты с отображением браузера:

```powershell
pytest -m smoke --headed
```

Запустить конкретный файл:

```powershell
pytest tests/test_inventory.py -v
```

Запустить тест навыков:

```powershell
pytest tests/test_skills.py
```

## Подход к тестированию

Основные принципы проекта:

- тестируемое действие выполняется через UI;
- предусловия по возможности создаются через API;
- итоговое бизнес-состояние проверяется через API;
- перед каждым тестом пользователь сбрасывается в известное состояние;
- каждый UI-тест получает отдельный `BrowserContext`;
- Page Object и дополнительные fixtures добавляются после появления повторяющегося кода.

API используется для:
- подготовки тестовых данных;
- сброса тестовых пользователей в начальное состояние;
- проверки состояния данных после действий через UI.

Перед выполнением теста пользователь сбрасывается в заранее известное состояние через API. Это позволяет сделать тесты независимыми и воспроизводимыми.

Для сброса используется служебный endpoint `POST /api/v1/account/reset`. Он не входит
в публичный контракт из `API_REFERENCE.md` и предназначен для тестовой подготовки.

Данные авторизации VK хранятся в переменных окружения и не добавляются в репозиторий.

## План развития smoke-покрытия

Smoke-набор предназначен для проверки основного критичного функционала приложения.

Реализовано:

- Инвентарь — экипировка и снятие предмета
- Навыки — прокачка навыка «Меч» до первого уровня и списание LP

Планируется:

- Биржа — обмен валют
- Почта — отправка предмета
- Профиль — выбор титула, рамки, аватара и фона
- Гильдия — создание, вступление, исключение участника и роспуск

## CI

Smoke-тесты запускаются в GitHub Actions на push и pull request. В настройках
репозитория нужно создать Actions secrets:

- `BASE_URL`
- `API_URL`
- `VK_LAUNCH_PARAMS_USER_1`
- `VK_LAUNCH_PARAMS_USER_2`

Workflow устанавливает Python 3.14 и Chromium, после чего запускает:

```text
pytest -m smoke --browser chromium
```

## Известный технический долг

- Слот экипировки головы временно выбирается через `locator("svg").nth(3)`.
- Кнопка изучения навыка «Меч» временно выбирается как первая кнопка
  `Учить (10 LP)`.

Для устойчивых локаторов frontend должен предоставить `data-testid` или доступные
имена для слотов экипировки и кнопок конкретных навыков.
