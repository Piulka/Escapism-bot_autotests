# QA findings

Живой backlog дефектов и улучшений, найденных при исследовании Escapism и
разработке автотестов.

Статусы: `New`, `Confirmed`, `In progress`, `Fixed`, `Won't fix`.
Приоритеты: `P0` — блокирует критичный путь, `P1` — значимый риск,
`P2` — заметная проблема, `P3` — улучшение.

## API и инфраструктура

### API-001 — Периодические продолжительные ответы 502

- Тип: bug / test environment stability
- Приоритет: P1
- Статус: Confirmed
- Затронуто: `GET /api/v1/profile`, `GET /api/guild`,
  `GET /api/guild/members`, `GET /api/guild/applications`,
  `POST /api/v1/account/reset`, `POST /api/guild/leave`
- Наблюдение: endpoint может возвращать `502 Bad Gateway` несколько раз подряд
  после успешной UI-операции или во время setup/cleanup. В UI это также
  воспроизводится экраном `Не удалось загрузить данные → Повторить` при открытии
  каталога гильдий сразу после успешного создания.
- Влияние: корректный пользовательский сценарий становится красным из-за
  недоступности проверки или teardown; полный прогон заметно замедляется.
- Workaround: ограниченный retry только для безопасных GET и idempotent reset;
  пользовательские mutation POST автоматически не повторяются.
- Ожидание: найти причину gateway errors и обеспечить стабильный test API.

### API-002 — Account reset не очищает связанные состояния

- Тип: testability improvement
- Приоритет: P2
- Статус: Confirmed
- Затронуто: guild membership и личный warehouse.
- Наблюдение: `POST /api/v1/account/reset` возвращает базовый inventory/profile,
  но может оставить гильдию и содержимое личного склада.
- Влияние: тесты вынуждены иметь отдельный cleanup и восстанавливать дельты.
- Ожидание: документировать контракт reset либо добавить полный test reset с
  очисткой guild/mail/warehouse и других связанных сущностей.

### API-003 — Контракт exchange изменился без актуальной документации

- Тип: documentation defect
- Приоритет: P2
- Статус: Confirmed
- Наблюдение: webapp начал передавать `minAmountOut`, но поле отсутствовало в
  описании `POST /api/exchange`.
- Влияние: контрактный assertion smoke-теста обнаружил незадокументированное
  изменение.
- Workaround: локальная `API_REFERENCE.md` дополнена полем.

## UX/UI и accessibility

### UI-001 — У кнопки фильтров инвентаря нет доступного имени

- Тип: accessibility / testability
- Приоритет: P2
- Статус: Confirmed
- Наблюдение: button содержит только `svg.lucide-funnel`, без `aria-label` и
  видимого текста.
- Влияние: screen reader не объясняет действие; тест использует CSS-класс иконки.
- Ожидание: добавить `aria-label="Фильтры"`.

### UI-002 — Equipment slots не имеют стабильных locator

- Тип: accessibility / testability
- Приоритет: P2
- Статус: Confirmed
- Наблюдение: все 8 equipment slots реализованы как кликабельные `div` без
  `role`, `aria-label` и `data-testid`; smoke-тест временно использует
  `locator("svg").nth(3)` для слота головы.
- Влияние: изменение порядка SVG может сломать тест без изменения функции.
- Ожидание: accessible button name или `data-testid` с ключом equipment slot.

### UI-003 — Строка участника гильдии не является доступной кнопкой

- Тип: accessibility / testability
- Приоритет: P2
- Статус: Confirmed
- Наблюдение: управление участником открывается кликом по тексту ника; button role
  и доступное имя отсутствуют.
- Ожидание: использовать `<button>` либо добавить корректные role, keyboard
  interaction и accessible name.

### UI-004 — Карточки выбора почтовых вложений не имеют стабильного имени

- Тип: accessibility / testability
- Приоритет: P2
- Статус: Confirmed
- Наблюдение: элементы временно выбираются по позиции `div.aspect-square`.
- Влияние: сортировка inventory способна выбрать другое вложение.
- Ожидание: accessible name с названием предмета и количеством либо test id с
  item ID.

### UI-005 — Unread-индикатор письма не имеет семантического состояния

- Тип: accessibility / testability
- Приоритет: P3
- Статус: Confirmed
- Наблюдение: состояние проверяется по CSS-классу.
- Ожидание: добавить текст для screen reader, `aria-label` или `data-testid` с
  явным read/unread state.

### UI-006 — Кнопка направления обмена не имеет доступного имени

- Тип: accessibility / testability
- Приоритет: P2
- Статус: Confirmed
- Наблюдение: locator строится по `svg.lucide-arrow-down-up`.
- Ожидание: динамический `aria-label`, например `Обменять золото на серебро`.

### UI-007 — Крестик карточки предмета не имеет доступного имени

- Тип: accessibility / testability
- Приоритет: P2
- Статус: Confirmed
- Наблюдение: основной item dialog содержит первым элементом button только с
  иконкой закрытия; доступное имя отсутствует.
- Влияние: screen reader не объясняет действие, а тест вынужден выбирать первую
  кнопку внутри dialog.
- Ожидание: добавить `aria-label="Закрыть карточку предмета"`.

### UI-008 — Заблокированные действия предмета теряют назначение

- Тип: UX / accessibility
- Приоритет: P2
- Статус: Confirmed
- Наблюдение: после lock четыре разных действия получают одинаковое accessible
  name `Заблокировано`.
- Влияние: пользователь screen reader не может определить, какое действие было
  запрещено; сообщения теста также теряют контекст.
- Ожидание: сохранить название действия и объяснить причину, например
  `Надеть — недоступно: предмет заблокирован`.

## Правила добавления findings

- Не записывать предположение как подтверждённый bug.
- Для воспроизводимого дефекта указывать экран, действие, фактический и ожидаемый
  результат.
- Проблемы тестового стенда отделять от продуктовых дефектов.
- После исправления сохранять запись и менять статус на `Fixed` с версией/датой.
