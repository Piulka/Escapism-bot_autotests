# Regression roadmap

## Цель

Расширять покрытие после завершённого smoke-набора, сохраняя тесты независимыми,
диагностируемыми и близкими к реальному коммерческому проекту. Пользовательские
действия выполняются через UI, setup и итоговое бизнес-состояние по возможности
контролируются через API.

## Правила реализации

- Один тест проверяет один бизнес-смысл, а не весь экран целиком.
- Похожие проверки с одинаковым flow параметризуются и остаются отдельными test
  nodes в отчёте.
- Тесты не зависят от порядка запуска и не используют состояние предыдущего теста.
- Изменённые предметы, валюта, почта и guild-состояние восстанавливаются в
  `finally` или служебным reset.
- Повторяющийся код выносится только после появления реального повторения.
- Предпочтение отдаётся role, accessible name, label и test id. Позиционные CSS/XPath
  локаторы фиксируются как технический долг.
- Для списков ожидаемый результат рассчитывается по API, а не дублируется большим
  хардкодом в тесте.
- Базовая проверка вёрстки означает: ключевой контрол видим, находится внутри
  viewport, имеет ненулевой размер, доступен для клика и не перекрыт другим
  элементом. Pixel-perfect сравнения без стабильных эталонов не используются.

## Отложено до готовности продукта/setup

- Разбор предмета: endpoint отсутствует в текущей API-документации.
- Craft, shop и knowledge: UI сообщает, что разделы находятся в разработке.
- Market: endpoints обозначены как stub.
- Полноценная сортировка guild members: желательно минимум три тестовых участника
  или API setup состава.
- Skill validation на исчерпанных LP: нужен быстрый setup остатка LP, чтобы не
  выполнять десятки одинаковых UI-действий.

## Критерий готовности блока

- Новые тесты проходят отдельно и вместе со всем соответствующим пулом.
- Smoke-пул остаётся зелёным.
- Нет зависимости от порядка выполнения.
- Изменяемое состояние восстанавливается после успешного и неуспешного сценария.
- README и этот roadmap отражают фактическое покрытие и известный технический долг.
- Новые подтверждённые проблемы добавлены в `QA_FINDINGS.md`.
